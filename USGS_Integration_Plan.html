2. Complete Data Flow Architecture

Incidents Flow (No Changes)

Phoenix Fire Active Incidents API ↓ Fetch every 30 seconds ↓ Firebase Realtime Database Cache ↓ IncidentsProvider ↓ MapBoxWidget ↓ PointAnnotationManager (Incident Markers) ↓ Dynamic icons based on incident type

Fire Stations Flow (New USGS)

USGS National Structures API (carto.nationalmap.gov) ↓ Download GeoJSON (one-time or weekly update) ↓ Parse & Convert Coordinates (Web Mercator → WGS84) ↓ Hive Local Cache (~180-200 KB for Arizona) ↓ FireStationService (cache-first) ↓ IncidentsProvider ↓ MapBoxWidget ↓ FireStationAnnotationManager (Fire Station Markers) ↓ Static fire station icon

Combined Display

Both data types display simultaneously on the same Mapbox map:

  • Incidents: Real-time, dynamic markers (fire/medical/rescue icons)
  • Fire Stations: Cached, static markers (fire station icon)
  • Toggle control: User can show/hide fire stations
  • Click handlers: Separate bottom sheets for each type

3. Detailed Implementation Steps

Phase 1: Storage & Download Infrastructure

Estimated Time: 8-10 hours

Step 1.1: Add Dependencies (15 minutes)

dependencies: hive: ^2.2.3 # Local NoSQL database hive_flutter: ^1.1.0 # Flutter integration proj4dart: ^2.1.0 # Coordinate conversion workmanager: ^0.5.2 # Background updates dev_dependencies: hive_generator: ^2.0.1 # Code generation build_runner: ^2.4.6 # Build tool

Step 1.2: Create Hive Models (30 minutes)

Create lib/models/cached_fire_station.dart:

  • CachedFireStation class with Hive annotations
  • Fields: id, name, lat, lng, address, loadDate, adminType
  • FireStationCache metadata class
  • Run code generation: flutter pub run build_runner build

Step 1.3: Build USGS Service (2 hours)

Create lib/services/usgs_service.dart:

  • Query USGS API for Arizona state-wide data
  • Handle pagination (max 2000 records per request)
  • Convert Web Mercator to WGS84 using proj4dart
  • Parse GeoJSON FeatureCollection
  • Extract: NAME, ADDRESS, CITY, STATE, ZIPCODE, LOADDATE, ADMINTYPE
  • Error handling with retry logic
  • Update detection method using LOADDATE field

Step 1.4: Build Cache Service (1.5 hours)

Create lib/services/fire_station_cache_service.dart:

  • Initialize Hive boxes on app start
  • saveStations() - Store fire stations in Hive
  • loadStations() - Load from cache
  • clearCache() - Clear and re-download
  • shouldCheckForUpdates() - Check if weekly refresh needed
  • Store metadata: lastDownloadDate, maxLoadDate, recordCount

Step 1.5: Initialize Hive (15 minutes)

Update lib/main.dart:

  • Add await FireStationCacheService.instance.init(); before runApp()
  • Register Hive adapters
  • Open Hive boxes

Step 1.6: Add SharedPrefs Keys (15 minutes)

Update lib/utils/shared_prefs.dart:

  • Add fireStationSource key (for future toggle support)
  • Add usgsLastCheckDate key for update tracking

Phase 2: Service Layer Migration

Estimated Time: 4-6 hours

Step 2.1: Update FireStationService (2 hours)

Modify lib/services/fire_station_service.dart:

  • Add getFireStationsFromUSGS() method
  • Implement cache-first loading:
    1. Check Hive cache first
    2. If cached and not expired: return immediately
    3. If not cached or force refresh: download from USGS
    4. Save to cache after download
  • Remove Google Places implementation (direct switch)
  • Add forceRefreshUSGS() method
  • Background update check (weekly)
  • Error handling with cache fallback

Step 2.2: Update FireStation Model (30 minutes)

Modify lib/models/fire_station_model.dart:

  • Add FireStation.fromUSGS() factory constructor
  • Map USGS fields to FireStation properties
  • Remove Google Places factory (direct switch)

Step 2.3: Update IncidentsProvider (1.5 hours)

Modify lib/providers/incidents_provider.dart:

  • Update fetchFireStations() to use USGS service
  • Add forceRefresh parameter
  • Add state tracking: _fireStationSource
  • Add forceRefreshFireStations() method
  • Keep callback support for incremental loading

Phase 4: Background Updates

Estimated Time: 4-5 hours

Step 4.1: Add WorkManager (15 minutes)

Already added in Phase 1 dependencies.

Step 4.2: Implement Background Service (2 hours)

Create lib/services/background_update_service.dart:

  • Initialize WorkManager
  • Register periodic task (weekly frequency)
  • Background callback (runs in separate isolate):
    1. Check USGS for updates using LOADDATE
    2. If updates available: auto-download
    3. Save to Hive cache
    4. Log results
  • Cancel/reschedule methods

Step 4.3: Initialize Background Updates (30 minutes)

Update lib/main.dart:

  • Call BackgroundUpdateService.initialize()
  • Schedule weekly update check

Step 4.4: iOS Background Configuration (1 hour)

Update ios/Runner/Info.plist:

<key>UIBackgroundModes</key> <array> <string>fetch</string> <string>processing</string> </array>

Step 4.5: Android Configuration (30 minutes)

WorkManager permissions already configured in manifest. No changes needed.

14. Appendix: USGS API Details

API Endpoint

https://carto.nationalmap.gov/arcgis/rest/services/structures/mapserver/16/query

Key Parameters

Parameter Value Description
f geojson Output format (GeoJSON recommended)
where STATE = 'AZ' SQL WHERE clause for filtering
outFields * Return all fields
returnGeometry true Include coordinate data
resultRecordCount 2000 Max records per request (pagination if needed)

Response Fields

  • NAME: Station name
  • ADDRESS: Street address
  • CITY: City name
  • STATE: State abbreviation (AZ)
  • ZIPCODE: ZIP code
  • LOADDATE: Last update timestamp (Unix milliseconds)
  • ADMINTYPE: Federal/Tribal/State/County/Municipal/Private/Unknown
  • geometry: Point coordinates (Web Mercator EPSG:102100)
